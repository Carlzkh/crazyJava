# 项目注解对照

每一行都是这个仓库里真实用过的注解。同一分类的行放在一起。

「不写注解的代码」不是把功能删掉，而是不用这一个注解时，要自己写哪些代码才能接近同样的效果。替代写法里有时还会出现别的注解，因为那是更底层的登记方式。

| 注解分类 | 注解 | 用法 | 作用 | 写注解的代码 | 不写注解的代码 |
|----------|------|------|------|----------------|----------------|
| 启动 | `@SpringBootApplication` | 只贴在启动类上 | 建容器、按 pom 自动配置、扫描所在包 | `@SpringBootApplication`<br>`public class CrazyJavaApplication` | 拆成三个注解，效果相同：`@SpringBootConfiguration`、`@EnableAutoConfiguration`、`@ComponentScan` |
| 组件声明 | `@Component` | 贴在不好归类的类上，如 `LogAspect`、`RequestLogInterceptor`、`EnvNameLogger` | 启动时创建这一个对象放进容器 | `@Component`<br>`public class RequestLogInterceptor` | 配置类里手动创建：`@Bean public RequestLogInterceptor requestLogInterceptor() { return new RequestLogInterceptor(); }` |
| 组件声明 | `@Service` | 贴在业务类 `UserService` 上 | 启动时创建业务对象，并交给需要它的构造方法 | `@Service`<br>`public class UserService` | 去掉类上的 `@Service`，改到配置类：`@Bean public UserService userService(UserRepository userRepository) { return new UserService(userRepository); }`。两处不要同时留 |
| 组件声明 | `@Repository` | 贴在 `UserRepository` 上 | 启动时创建数据访问对象。和 `@Service` 的差别是这一层只转发，不写业务规则 | `@Repository`<br>`public class UserRepository` | `@Bean public UserRepository userRepository(UserMapper userMapper) { return new UserRepository(userMapper); }` |
| 组件声明 | `@Configuration` | 贴在 `WebMvcConfig` 这类配置类上 | 这个类放进容器，里面的 `@Bean` 方法会在启动时被调用 | `@Configuration`<br>`public class WebMvcConfig` | 若只是普通类，里面的 `@Bean` 方法不会执行。要达到同样效果，就得在另一个已被扫描的配置类里 `new` 出这些对象并 `@Bean` 登记 |
| 组件声明 | `@RestController` | 贴在 `UserController`、`HelloController` 上 | 既放进容器，又把 `return` 写成 JSON，而不是网页名 | `@RestController`<br>`public class UserController` | 写成 `@Controller`，每个接口方法再加 `@ResponseBody`。少了 `@ResponseBody` 时，返回的字符串会被当成页面名 |
| Web 请求 | `@RequestMapping` | 贴在类或方法上。类上是整组接口的前缀 | 把地址和方法对上。`${api.version}` 启动时换成 `v1` | `@RequestMapping("/api/${api.version}/users")` | 每个方法都写完整地址，例如 `@GetMapping("/api/v1/users")`。版本号一改，所有方法都要改 |
| Web 请求 | `@GetMapping` | 贴在查询、导出方法上 | 只接 GET。无路径时用类上的前缀；`/export`、`/{id}` 再拼到前缀后面 | `@GetMapping`<br>`public Result getUsersByPage(...)` | `@RequestMapping(method = RequestMethod.GET)`。不用任何映射注解时，要自己写 Servlet，在 `doGet` 里处理 |
| Web 请求 | `@PostMapping` | 贴在 `createUser`、`/test-tx` 上 | 只接 POST。和 GET 可以共用同一个路径 | `@PostMapping`<br>`public Result createUser(...)` | `@RequestMapping(method = RequestMethod.POST)` |
| Web 请求 | `@PutMapping` | 贴在 `setUserById` 上，路径 `/{id}` | 只接 PUT，用来更新某一条 | `@PutMapping("/{id}")` | `@RequestMapping(value = "/{id}", method = RequestMethod.PUT)` |
| Web 请求 | `@DeleteMapping` | 贴在按 id 删除和 `/batch` 上 | 只接 DELETE | `@DeleteMapping("/{id}")` | `@RequestMapping(value = "/{id}", method = RequestMethod.DELETE)` |
| 参数绑定 | `@RequestBody` | 贴在 `createUser`、`setUserById`、批量删除的参数上 | 把请求体 JSON 变成 `User` 或 `List` | `createUser(@RequestBody User user)` | 自己读 `request.getReader()`，再用 Fastjson 的 `JSON.parseObject` 转成 `User` |
| 参数绑定 | `@RequestParam` | 贴在分页、搜索、导出的参数上 | 读 `?page=1&size=10&name=张`。`defaultValue` 是没传时的值，`required = false` 表示可以不传 | `@RequestParam(defaultValue = "1") Integer page` | 自己写 `request.getParameter("page")`，没有这个参数时自己补 `"1"`，再 `Integer.parseInt` |
| 参数绑定 | `@PathVariable` | 贴在路径里的 `{id}` 上 | `DELETE /api/v1/users/3` 时，参数 `id` 是 `3` | `deleteUser(@PathVariable Long id)` | 自己截取 URI 最后一段，再 `Long.parseLong` |
| 参数校验 | `@Valid` | 贴在 Controller 的 `User` 参数上，和 `@RequestBody` 一起 | 进方法之前，按字段上的规则检查。失败则方法体不执行 | `createUser(@Valid @RequestBody User user)` | 方法开头自己检查：`if (user.getName() == null) throw ...`。字段上的 `@NotNull` 不会自动跑 |
| 参数校验 | `@NotNull` | 贴在 `User.name`、`User.age` 上 | 值为 `null` 或 JSON 里没有该字段时失败。挡不住空字符串 `""` | `@NotNull(message = "{user.name.notnull}")`<br>`private String name;` | 在 Service 里写 `if (name == null) throw new BusinessException(...)` |
| 参数校验 | `@Size` | 贴在姓名上，`min = 1, max = 50` | 限制字符串长度。空字符串会被 `min = 1` 拦住 | `@Size(min = 1, max = 50)`<br>`private String name;` | `if (name.length() < 1 \|\| name.length() > 50) throw ...` |
| 参数校验 | `@Min` / `@Max` | 贴在年龄上，0 到 150 | 数字超出范围就失败。16 岁能通过，未满 18 岁是 Service 里另抛的业务异常 | `@Min(0) @Max(150)`<br>`private Integer age;` | `if (age < 0 \|\| age > 150) throw ...` |
| 异常处理 | `@RestControllerAdvice` | 贴在 `GlobalExceptionHandler` 类上 | 所有 Controller 抛出的异常都可以送到这个类，返回值写成 JSON | `@RestControllerAdvice`<br>`public class GlobalExceptionHandler` | 每个接口方法自己 `try-catch`。漏一个，失败格式就不一样，或者变成 Spring 默认的错误页 |
| 异常处理 | `@ExceptionHandler` | 贴在处理方法上，括号里是异常类型 | 只接这一种异常。`BusinessException` 要单独一个方法，否则会掉进 `RuntimeException`，变成 `50000` | `@ExceptionHandler(BusinessException.class)`<br>`public Result handleBusinessException(...)` | `catch (BusinessException e) { return Result.error(e.getCode(), e.getMessage()); }`，并且每个接口都写一遍 |
| 异常处理 | `@ResponseStatus` | 贴在异常处理方法上 | 指定这次 HTTP 状态码，例如校验失败是 400，系统错误是 500 | `@ResponseStatus(HttpStatus.BAD_REQUEST)` | `response.setStatus(400)`。不写时，即使 body 里是错误，HTTP 状态码也可能仍是 200 |
| 生命周期 | `@PostConstruct` | 贴在无参方法上，如 `UserService.init` | 依赖注入完成后调用一次。一个类标了两个就会两个都执行 | `@PostConstruct`<br>`public void init()` | 在构造方法最后自己调用 `init()`。差别是构造方法里依赖刚传进来，而这个注解保证容器侧的注入已经结束 |
| 生命周期 | `@PreDestroy` | 贴在 `UserService.destroy` 上 | 正常关闭程序时调用一次 | `@PreDestroy`<br>`public void destroy()` | 自己注册关闭钩子：`Runtime.getRuntime().addShutdownHook(...)`。直接杀进程时，两种都可能来不及跑 |
| 配置 | `@ConfigurationProperties` | 贴在 `AppProperties` 上，`prefix = "app"` | 把 `app.env-name`、`app.page-size` 填进 `envName`、`pageSize`。短横线对应驼峰，必须有 setter | `@ConfigurationProperties(prefix = "app")`<br>`public class AppProperties` | 每个字段一个 `@Value`：`@Value("${app.env-name}") String envName`。项一多，构造方法参数会很长 |
| 事务 | `@Transactional` | 贴在 `deleteUsersByIds`、`testTransaction` 上 | 这个方法里的多次改库当成一件事。抛运行时异常就整段撤销 | `@Transactional(rollbackFor = Exception.class)`<br>`public void testTransaction(Long id)` | 自己拿连接，`setAutoCommit(false)`，成功 `commit`，`catch` 里 `rollback`。类内部自己调用自己时，注解也不会按期望生效 |
| 切面 | `@Aspect` | 贴在 `LogAspect` 上 | 声明这个类是切面，里面的通知才会包到目标方法上 | `@Aspect`<br>`public class LogAspect` | 在每个 Controller 方法开头和结尾手写打日志的代码。漏一个方法就没有日志 |
| 切面 | `@Pointcut` | 贴在一个空方法上，括号里是匹配规则 | 给「哪些方法要被包住」起一个名字，供 `@Around` 引用 | `@Pointcut("execution(* com.example.crazyjava.controller..*.*(..))")`<br>`public void controllerMethod()` | 把这串 `execution` 直接写进 `@Around("execution(...)")`。多处要用同一规则时，会复制好几遍 |
| 切面 | `@Around` | 贴在 `LogAspect.around` 上 | 方法执行前后都能写代码。`proceed()` 才是去调用 Controller 方法 | `@Around("controllerMethod()")`<br>`public Object around(...)` | 只在方法前打日志可以用 `@Before`，只在方法后打可以用 `@After`。要前后都管、还能决定是否调用原方法，就得用 `@Around` |
| 持久层 | `@Mapper` | 贴在 `UserMapper` 接口上 | MyBatis 按 XML 的 `id` 生成实现。接口没有方法体 | `@Mapper`<br>`public interface UserMapper` | 在启动类上写 `@MapperScan("com.example.crazyjava.mapper")`，接口上就可以不写 `@Mapper`。两种都是在登记「这个包里的接口要生成实现」 |
| 持久层 | `@Param` | 贴在 Mapper 方法的参数上 | XML 里用这个名字取参数，例如 `#{name}` | `findByName(@Param("name") String name)` | 只有一个参数时，XML 可以写 `#{id}` 或 `#{_parameter}`。两个及以上参数时，不写 `@Param`，名字容易对错 |
| 持久层 | `@Options` | 贴在 `insert` 上 | 插入后把数据库自增主键写回 `user.id` | `@Options(useGeneratedKeys = true, keyProperty = "id")`<br>`void insert(User user);` | 同样的两句话写在 XML 的 `<insert useGeneratedKeys="true" keyProperty="id">` 上。注解和 XML 写一处即可，不要两处互相打架 |
| 持久层 | `@MappedTypes` | 贴在 `GenderTypeHandler` 上 | 告诉 MyBatis：Java 类型是 `Gender` 时用这个处理器 | `@MappedTypes(Gender.class)` | 在 `UserMapper.xml` 的结果或参数上写 `typeHandler=...GenderTypeHandler`。每个用到性别的字段都要写 |
| 持久层 | `@MappedJdbcTypes` | 和上面贴在同一个类上 | 告诉 MyBatis：数据库这一列的 JDBC 类型是 `TINYINT` | `@MappedJdbcTypes(JdbcType.TINYINT)` | 不声明时，要在每条 SQL 上自己指定类型和处理器，否则枚举和数字对不上 |
| 代码生成 | `@Data` | 贴在 `User`、`Result`、`PageResult` 上。Lombok 的注解，不把类放进容器 | 编译时生成 getter、setter、`equals`、`toString` | `@Data`<br>`public class User` | 每个字段手写 `getName`、`setName`。不写的话 `user.getAge()` 编不过 |
| 代码生成 | `@Getter` | 贴在 `Gender`、`ResultCodeEnum`、`BusinessException` 上 | 只生成 getter。这些字段是 `final`，不需要 setter | `@Getter`<br>`public enum Gender` | 手写 `public int getCode() { return code; }` |
| 代码生成 | `@AllArgsConstructor` | 贴在 `ResultCodeEnum` 上 | 生成带全部字段的构造方法。枚举常量 `USER_NOT_FOUND(60000, "用户不存在")` 会调用它 | `@AllArgsConstructor`<br>`public enum ResultCodeEnum` | 手写 `ResultCodeEnum(Integer code, String msg) { this.code = code; this.msg = msg; }` |
| 代码生成 | `@Slf4j` | 贴在需要打日志的类上 | 生成名为 `log` 的日志对象 | `@Slf4j`<br>`public class UserService` | `private static final Logger log = LoggerFactory.getLogger(UserService.class);` |
| 文档 | `@Tag` | 贴在 `UserController` 类上 | 接口文档里这一组归到「用户管理」。不影响接口能不能调用 | `@Tag("用户管理")` | 不写文档分组。接口照常访问，文档里没有这个标题 |
| 文档 | `@Operation` | 贴在搜索方法上 | 文档里这一个接口的说明。不影响调用 | `@Operation(summary = "查询用户列表（分页 + 多条件搜索）")` | 不写时，文档用方法名 `searchUsers` 当标题 |
| 测试 | `@Test` | 贴在测试方法上 | 让 JUnit 把这个方法当成一条测试去跑 | `@Test`<br>`void getUserById_shouldReturnUser_whenIdExists()` | 写一个 `main`，自己调用方法再 `if` 判断结果。没有失败统计，也不能被 `mvn test` 收集 |
| 测试 | `@BeforeAll` | 贴在 `FastjsonGenderTest` 的准备方法上 | 全部测试开始前执行一次 | `@BeforeAll`<br>`static void init()` | 在每条 `@Test` 开头复制同一段准备代码 |
| 测试 | `@ExtendWith` | 贴在 `UserServiceTest` 类上 | 启用 Mockito 扩展，后面的 `@Mock` 才会生效 | `@ExtendWith(MockitoExtension.class)` | 在 `@BeforeEach` 里手写 `MockitoAnnotations.openMocks(this)` |
| 测试 | `@Mock` | 贴在 `UserRepository` 字段上 | 造一个假的 Repository，不连数据库 | `@Mock`<br>`private UserRepository userRepository;` | `UserRepository userRepository = Mockito.mock(UserRepository.class);` |
| 测试 | `@InjectMocks` | 贴在被测的 `UserService` 上 | 把上面的假 Repository 注入进 `UserService` | `@InjectMocks`<br>`private UserService userService;` | `UserService userService = new UserService(userRepository);`。构造方法已经能传入依赖时，这行更直接 |
| 编译器 | `@Override` | 贴在重写或实现的方法上，如 `match`、`preHandle` | 方法名写错就编译失败，避免悄悄变成一个新方法 | `@Override`<br>`public boolean preHandle(...)` | 不写也能重写。写成 `preHanlde` 时编译器发现不了，父类那个方法仍然没人实现 |
| 编译器 | `@SuppressWarnings` | 贴在 `SingletonTest`、个别反序列化方法上 | 告诉编译器：这个警告我知道，不要再标出来 | `@SuppressWarnings("unchecked")` | 不写时，功能不变，只是编辑器会多一条警告 |
| 自定义注解 | `@Target` | 贴在你自己定义的注解上，如 `MyService` | 限制这个注解能贴在哪。`ElementType.TYPE` 是类，`FIELD` 是字段 | `@Target(ElementType.TYPE)`<br>`public @interface MyService` | 不写时，这个注解类、方法、字段上都能贴，容易贴错位置 |
| 自定义注解 | `@Retention` | 贴在 `MyService`、`MyAutowired`、`MyComponent` 上 | `RUNTIME` 表示程序跑起来还能读到这个注解。`MiniApplicationContext` 靠反射找它们 | `@Retention(RetentionPolicy.RUNTIME)` | 改成 `SOURCE` 或 `CLASS` 时，运行期间反射看不到，迷你容器扫描不到这些类 |
| 自定义注解 | `@MyService` / `@MyComponent` | 贴在 `OrderService`、`OrderController` 上 | 给你自己的迷你容器看：请创建这个类。Spring 的 `@Service` 不认识它们 | `@MyService`<br>`public class OrderService` | 在 `MiniApplicationContext` 里手写 `beans.put("orderService", new OrderService())`。类一多就要改扫描代码 |
| 自定义注解 | `@MyAutowired` | 贴在 `OrderController` 的字段上 | 迷你容器扫描字段，把同类型的对象填进去 | `@MyAutowired`<br>`private OrderService orderService;` | 创建完对象后手写 `controller.orderService = orderService;`。字段必须能被赋值，不能是 `private` 又没有放开访问 |
